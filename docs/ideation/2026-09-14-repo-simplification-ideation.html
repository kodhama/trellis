Seven ranked directions for making the repository much smaller, chosen from 47 raw ideas that were merged into 18 candidates and checked against the repository.

Codebase Context

What ships is about 8 KB of rule text. A session receives rules.md (6.0 KB), a posture header (0.7 KB) and the active rows (1.1 KB). The 29 KB invariants.md is referenced from that text but not injected.

A consumer touches one file. .trellis/rules.toml holds strictness and 16 active rows, or governed = false. The two floor rows apply whatever the file says. The shipped presets both switch every row on, and the two postures differ by one sentence in the ~8 KB block. Nothing a consumer runs reads profiles/, core/lexicon.md, core/schemas/typed-artifacts.md or core/invariants/trellis-invariants-v1.md; only Go tests read them.

One invariant passes through eight steps before a session sees it: the catalog entry, a go:generate copy into cli/assets/, parsing in apply.go, rendering by trellis payload into 14 reference files plus checksums, a manifest baked into install.sh, a VERSION bump that release-guard enforces, one of three delivery channels, and reconciliation against the consumer's rules.toml.

Decisions are the rulebook. AGENTS.md says "The method lives in docs/decisions/, not restated here — a decision is the current truth". Records are append-only and superseded by forward pointer, so learning a current rule can mean walking a chain such as 0011 → 0079 → 0085 → 0097. Code is coupled to the records: tests cite 53 distinct decision ids and read 23 decision files by path, and 63 of the 98 ids are cited somewhere in cli/, the plugin, install.sh or .github/. The corpus grew by 12 records in June, 40 in July, 14 in August and 15 in the first half of September.

Known consumers. The only record, decision-0081, is a read-only inspection of the maintainer's machine listing this repository, math-quest and six Kodhama repositories. No record gives a count of outside installs. Claude Code cloud sessions receive the rules only when a setup script installs the plugin before launch, or through install.sh's rendered .claude/rules/trellis.md; the project-scope enabledPlugins setting does not reach cloud (plugins/trellis/README.md).

The one experiment that ran. research-0012 measured one rule on one task, 20 runs per arm: control 95%, rule text removed 0%, rule switched off in rules.toml 0%. Switching the row off moved behaviour by 95 points (p = 3×10⁻¹⁰), and decision-0053 acted on that result. The note says "A positive result generalizes by assumption, not evidence."

Outside practice. Mature processes keep the decision log apart from the living specification: a Final PEP "is considered a historical document rather than a living specification", the Rust Reference is authoritative over accepted RFCs, and Oxide edits committed RFDs in place. IETF RFC 9110 folded a chain of superseded RFCs into one document. For agent instructions, the Claude Code documentation targets under 200 lines per CLAUDE.md, and one study found instruction adherence declining past roughly 150 instructions.

docs/solutions/ does not exist yet, so there were no captured learnings to draw on.

1. Decisions become history; living specs hold current truth

Idea 1Axis 1 · Where current truth livesConfidence 85%Complexity High
Description

A one-time consolidation reads all 98 records and sorts each into in force, spent or repealed. The in-force content moves into a few living spec documents that pull requests edit in place, for example one each for the rules, delivery, and repository and release. One final record states that the specs are the authority and the 98 records are history. That single full supersession replaces the clause-level pointers, the record set stays append-only, and git history is untouched.

From then on, AGENTS.md admits a new decision record only for a choice that is costly to reverse, the kind records 0001–0004 hold. Renames, moves, tool swaps, guard fixes and refinements become spec edits explained in the PR body, and superseded_in_part_by retires. Because new records are rare, they are named by date and slug as docs/plans/ already is, which retires .github/scripts/decision-id-guard.sh, its workflow, cli/decision_id_guard_test.go (697 lines) and the id-reservation rule in AGENTS.md.

Order inside the idea: re-point the decision-id citations in code and tests at spec sections first, while the conformance tests still check the migration.

Basis
  • direct: AGENTS.md:29-30, "The method lives in docs/decisions/, not restated here — a decision is the current truth, and a summary in this file only goes stale against it."
  • direct: 53 of 98 records carry a supersession pointer. decision-0089's frontmatter is a "~500-word run-on clause-by-clause diff against two later records". 0090:160-162: "That is a decision record with no decision in it".
  • direct: decision-id-guard.sh:8-11: "It happened three times … Nothing failed on any of them; a human noticed." 0089:44-45: a renumber touched "seven files on recurrence #3".
  • direct: tests cite 53 distinct decision ids and read 23 decision files by path.
  • external: PEP 1, RFC 9110, Oxide RFD 1, openfactory-core PR #80 (see Sources).
  • The maintainer: "Should have more specs and less decisions", and the pattern "was never a choice but something that emerged".
Rationale
An agent learns a current rule by reading one section instead of walking pointers. The admission rule is what stops the corpus growing back: it added 40 records in July, and four records plus about a dozen pointers on 13–14 September alone.
Downsides
The migration is large semantic work, and a wrong "spent" call drops a live clause, so each classification needs review. It needs a sweep of the 63 decision ids cited from code and CI. It abandons the append-only-as-truth practice that decision-0015 and decision-0082 rely on. Date-and-slug names are not strictly collision-free, only unlikely to clash once records are rare.

2. Rule configuration shrinks to an opt-out list

Idea 2Axis 2 · The rule modelConfidence 80%Complexity Medium
Description

.trellis/rules.toml becomes optional and holds a single key, disabled = ["slug", …]. No file means every rule applies. An unknown slug prints a warning and is ignored, and floor rules cannot be listed. strictness, seeded_from, the 16 active rows, rules-a.toml and rules-b.toml, the posture headers trellis-a.md and trellis-b.md, and the reconcile, quarantine and rewrite logic in both hooks are deleted.

A catalog change then never touches consumer config, because the file lists only what a project turned off. Deleting the file format entirely stays available later, if no project ever lists a rule.

Basis
  • direct: the two postures' rows are byte-identical and the ~8 KB blocks differ by one sentence. 0033:22: the posture lean is "descriptive, not enforced (nothing acts on it yet)".
  • direct: 0083:25: "A single unmatched row cost all sixteen rules, every session, until a human edited the file." 0083:47-49: the two causes of an unknown row "are indistinguishable at runtime".
  • direct: 0081:273: "Six consumer repos are still on the 14-row set". .trellis/rules.toml:21-22: floor rows "applies regardless of this row".
  • direct: research-0012: switching one row off moved behaviour 95 points, so the opt-out works and is worth keeping.
  • external: the International Building Code is adopted by reference, and cities publish only their local amendments.
  • The maintainer: "even the whole rule configuration is really interesting but likely overkill".
Rationale
The one measured lever, turning a rule off, survives. Most of the rest of the configuration layer exists to repair the drift that copying the full row set into every consumer creates.
Downsides
It changes a consumer-facing file format, so existing rules.toml files need a migration rule (read old rows once, or ask the project to replace the file). Removing postures removes a choice a project may have made, although nothing acts on it today. The reviewer found no support for the stronger "no file at all" variant: that removes the opt-out, and nothing establishes project-owned rule text as a supported replacement.

3. Claim only what ships; keep only evidence that ran

Idea 3Axis 5 · Evidence and outward storyConfidence 75%Complexity Medium
Description

The identity sentence in AGENTS.md, README and the brief changes from "fits, teaches, adapts, and guards whatever methodology a project uses" to what ships: invariants injected at session start on Claude Code and Codex, plus a remove skill. The brief moves to docs/research/ as the dated founding thesis, and README becomes the only home of positioning.

Scaffolding for the unbuilt half then retires: profiles/trellis-self.md, the expression-profile section of core/schemas/typed-artifacts.md, core/lexicon.md, the inert Active-subset code kept for the seed posture, and rubric check 10. The C1/C2 dials stay, because they appear in the shipped invariants reference.

In eval/, research-0011 records does-trellis-help as stopped, with the date and reason, and its 50 files, eval-scorecard.yml and check-scorecard.sh are deleted. The 181 run files of annotation-vs-absence move behind a git tag that research-0012 cites, and its runner stays.

Basis
  • direct: of the brief's §8 MVP, only invariant injection and the remove skill shipped. core/README.md says the conformance sub-agent "has no home in this repo".
  • direct: profiles/trellis-self.md:65-66: "authored by hand (Assess does not exist yet, cluster 1)". :68-73: "is expected, and is not independent validation".
  • direct: eval/experiments/README.md: "task suite ready, worker-prompt leak fixed (2026-07-20); full run pending". Only 2 of 11 tasks ran, and 03-finalize-and-ship/NOTES.md:1 reads "CONFOUNDED (kept as a methodological lesson, not a result)".
  • direct: the N=1 risk is restated at brief:193, brief:251, README.md:289-290 and research/0005:187.
  • external: ClinicalTrials.gov marks stopped studies Terminated with a "Why Stopped" reason instead of leaving them as recruiting.
Rationale
The broad claim is why artifacts for an unbuilt product exist and get repaired on every rename. A claim sized to the product turns those deletions into a consequence of scope, and removes about 230 eval files and one workflow while every result a decision used stays retrievable.
Downsides
Stopping does-trellis-help gives up the only prepared test of Trellis's cross-project claim. A git tag is harder to find than an archive. Repositioning is the maintainer's call and narrows what the landing site can say.

4. Guards follow their subject

Idea 4Axis 4 · Copies and guardsConfidence 70%Complexity Medium
Description

decision-0028's "a guard per pair" becomes "no committed copy that a build step or a deletion can remove; a guard is deleted in the same PR as its subject". decision-0071 already applied this rule once.

After idea 1 lands, the artifact-contract tests lose their subject and go with docs/rubrics/artifact-contract.md: corpus_conformance_test.go (1,593 lines), corpus_conformance_typed_test.go (459), artifact_contract_guard_test.go (784) and surface_matrix_guard_test.go (312, guarding a concept already deleted), 3,148 lines in all. The checks in docs_consistency_test.go that protect consumer-facing docs stay.

Copies go instead of being guarded: site/invariants.html is rendered from the catalog when Pages deploys, the assessableSlugs pin is parsed from the catalog, and counts in prose are deleted. The 90% coverage ratchet is reviewed against a short list of user-visible failure scenarios.

Basis
  • direct: cli/selfapply_test.go:11-25: "the drift that guard prevented is now structurally impossible rather than tested — there is no second copy to drift".
  • direct: cli/row_set_guard_test.go: "Do not grow this table by adding a count to prose — delete the count instead." README.md:278 still says "40+ decisions, 8+ research notes" against 98 and 11.
  • direct: the rubric says "nothing Trellis ships reads it (decision-0098 point 4)".
  • direct: AGENTS.md: "build-test is not a required status check on main, so a red is a signal, not a merge block." cli-ci.yml:85-89: "The floor is a ratchet… Raise it as coverage climbs."
  • external: Google's "Change-Detector Tests Considered Harmful": tests that fail on change without a behaviour change block refactoring.
Rationale
Under decision-0028 the guard suite grows with every copy. Under the deletion rule it shrinks, and the repository already has a working precedent.
Downsides
It reverses decision-0098, merged on 2026-09-14 at the maintainer's request. It has to run after idea 1, or the decision migration loses its checks. A site page rendered at deploy time is harder to review in a pull request.

5. One delivery path, and a hook that checks adoption and prints

Idea 5Axis 3 · Delivery to a consuming projectConfidence 60%Complexity High
Description

Pick one supported shape per host: the native plugin, installed before launch by a setup script in cloud sessions. Migrate the known repositories in one round of pull requests, and ship one last release whose hook detects the legacy states S1–S6 and prints the single fix. The next release deletes legacy detection, the coexistence branch and the migration nudges from staleness.sh and codex-context.mjs, the install.sh paths that serve only legacy states, and their tests. It also replaces decision-0073's seven-state set.

With idea 2 in place, the hook does two things: check that the project adopted Trellis, then print the rules minus the opt-out list. One short script could then serve both hosts. That retires the 1,751-line codex-context.mjs and its Node 20 requirement, the INVARIANTS_TOKEN string kept identical by hand across three files, and invariants_pointer_test.go (1,551 lines). Once nothing is assembled per session, removing the Go generator (811 lines of source) becomes a possible follow-on.

Basis
  • direct: 0081:266: "Measured on this machine today (read-only inspection of .trellis/rules.toml and ~/.claude/plugins/installed_plugins.json)", listing this repository, math-quest and six Kodhama repositories.
  • direct: decision-0073: "at least five components each hold their own private, partial enumeration" of delivery layouts.
  • direct: staleness.sh:129-141: "Fifteen defects … every one was found by a reviewer RUNNING the hook against a deliberately broken input."
  • direct: invariants_pointer_test.go:31-36: "the two implementations share no line to diff". codex-context.mjs: the token is "Byte-identical to the token staleness.sh matches… and to install.sh's own sed pattern".
  • direct: hook and install tests: plugin_hook 4,546 lines, install_script 3,019, codex_hook 2,748.
  • external: RFC 801. ARPANET hosts switched from NCP to TCP/IP on one day, which worked because the hosts were few and known.
Rationale
Legacy states cause most of the branching in about 4,500 lines of delivery code and about 10,000 lines of its tests, and they are where the fifteen-defect class comes from.
Downsides

decision-0081's list is a dated measurement on one machine, not an inventory. Unknown installs may sit on legacy shapes, and a last-migration release reaches only plugin installs, since vendored copies keep their frozen hook. Cloud delivery has to keep working through the setup-script path or install.sh's rendered file. Whether Codex can run a shell hook on every platform it supports is unverified.

Keep the adoption check
A hook that read nothing from the project would apply the rules in every repository a user-scope install opens. The check that the project opted in has to stay.

6. Delete cli-ci's path filter and the guards that police it

Idea 6Axis 4 · Copies and guardsConfidence 90%Complexity Low
Description
build-test runs on every pull request. Deleted with the filter: the 28-entry paths: list and its twin, ci_paths_guard_test.go (437 lines), and the dead entries .grove/**, decisions/** and research/** kept as tripwires. repo-hygiene.yml goes too, with its file-size and todos checks moving back into cli-ci, and the required hygiene check changes in the same ruleset edit. build-test can then become a required check.
Basis
  • direct: cli-ci.yml:11-14: "The paths filter is a coverage contract, not a convenience. build-test is the only job that runs go test, so EVERY file the suite reads out of the repo has to be selected here".
  • direct: cli-ci.yml:31-32: "Keep the two lists below identical; both are checked."
  • direct: repo-hygiene.yml:3-8: it runs "deliberately outside cli-ci: that workflow's paths filter is a coverage contract for the Go test suite".
  • external: GitHub leaves a required check pending when a path filter skips its workflow. That may be why build-test was never made required.
Rationale
Deleting one YAML block removes a meta-guard, a duplicate workflow, a manual sync rule and three permanent dead entries. Adding a test that reads a new file no longer needs a CI edit.
Downsides
Every pull request pays the full Go and Node run, including ones that touch only LICENSE or CODEOWNERS. The ruleset change on main has to land together with the workflow change, or merges wait on a check that no longer runs.

7. Comments say what the code does now; history lives in commits

Idea 7Axis 4 · Copies and guardsConfidence 70%Complexity Medium
Description
One house rule for shipped code and tests: a comment says what the code does now and why, and the story of how it got there goes in the commit message and PR. A ce-simplify-code pass then applies the rule to staleness.sh (about 65% comments), install.sh (659 of its 1,177 lines), codex-context.mjs and about 6,000 comment lines in the Go tests. The pass also removes many decision-id citations from code, which shrinks idea 1's sweep.
Basis
  • direct: staleness.sh:6-60: "this comment said the opposite until it was corrected… An earlier version of this note claimed exclusivity 'by construction', which was false."
  • direct: codex-context.mjs:1-33: "8000 (this constant's prior value) had no recorded rationale — it entered in commit 3490555 with none".
  • direct: site/index.html:552-557 keeps copy-editing commentary in shipped markup.
  • The maintainer: "even maybe running ce-simplify, although probably that's more for code".
Rationale
Someone debugging the Claude hook reads about 1,500 lines to reach the logic, and some of those comments were wrong. Git already keeps the history.
Downsides
Some comments are the only surviving statement of retired specs: the spec-0005 and spec-0007 markers in install.sh and the tests. Those need a new home in test names or a spec rather than deletion. If ideas 2 and 5 land first, much of this code is deleted anyway, so the pass is worth most after them.
